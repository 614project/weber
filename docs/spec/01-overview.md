# 1. 개요와 설계 원칙

[목차](../README.md) · 다음: [2. 기본 문법 →](02-syntax.md)

## 1.1 weber 는

weber 는 `키 { ... }` 와 `키: 값` 두 가지 모양만 쌓아 올려 웹페이지를 만드는 언어입니다.
한 줄이 HTML 요소인지, HTML 속성인지, CSS 인지, 자바스크립트인지는 쓰는 사람이 구분하지 않습니다. weber 가 문맥과 값을 보고 판별합니다.

```weber
div {
    class card
    padding 16px
    h2: "안녕하세요"
    button {
        "눌러 보세요"
        onclick: alert('반가워요')
    }
}
```

```html
<div class="card" style="padding: 16px">
  <h2>안녕하세요</h2>
  <button onclick="alert('반가워요')">눌러 보세요</button>
</div>
```

결과물은 HTML 파일 하나입니다. CSS 와 자바스크립트는 그 안에 들어가며, 실행할 때 필요한 라이브러리는 없습니다.

## 1.2 설계 원칙

weber 가 지향하는 방향은 **유연함과 융통성**입니다. 문법은 쓰는 사람에게 맞추고, 빠진 것은 weber 가 상식적으로 채웁니다.
다만 유연함이 "예측할 수 없음"이 되지 않도록, 아래 여섯 원칙을 함께 지킵니다. 이 명세의 모든 규칙은 이 원칙에서 나옵니다.

### 원칙 1. 뜻이 통하면 받아들인다

같은 뜻이라면 여러 표기를 허용합니다. 정해진 하나의 "올바른" 표기를 강요하지 않습니다.

```weber 예정
// 아래 네 줄은 모두 같은 뜻입니다.
font-size 16px
font-size: 16px
font-size: 16px;
font-size 16

// 블록은 중괄호로 써도 되고, 들여쓰기로 써도 됩니다.
nav { a: "홈" }
nav:
    a: "홈"
```

### 원칙 2. 빠진 것은 알아서 채운다

생략해도 뜻이 분명한 것은 생략할 수 있습니다. CSS 의 단위, `head` 와 `body`, `<meta charset>`, 목록을 감싸는 `ul` 같은 것들입니다.

```weber 예정
title: "내 페이지"
font-size 18          // → font-size: 18px
- 사과                 // → <ul><li>사과</li> ...
- 바나나
```

### 원칙 3. 추측은 드러낸다

weber 가 무언가를 추측하거나 채워 넣었다면, 쓰는 사람이 언제든 확인할 수 있어야 합니다.
컴파일러는 판별 결과(`classifications`)와 경고를 돌려주고, `--explain` 옵션은 적용한 추측을 모두 보여 줍니다. 자세한 내용은 [11장](11-diagnostics-output.md)에 있습니다.

### 원칙 4. 언제든 명시할 수 있다

모든 추측에는 그 추측을 이기는 명시적인 표기가 있습니다. **명시한 것은 언제나 추측보다 우선합니다.**

| 추측 | 명시하는 법 |
| --- | --- |
| `title` 을 속성으로 판별 | 블록을 붙이면 요소: `title { "제목" }` |
| `width 100` 을 img 의 속성으로 판별 | 단위를 쓰면 CSS: `width 100px` |
| `font-size 16` 에 px 를 붙임 | 직접 단위를 씀: `font-size 1rem` |
| head 와 body 를 자동으로 나눔 | `head { }`, `body { }` 를 직접 씀 |

### 원칙 5. 익숙한 것은 그대로 통한다

이미 아는 표기를 그대로 써도 동작해야 합니다.
평범한 CSS (`color: red;`), HTML 속성 표기 (`class="box"`), 평범한 자바스크립트를 붙여 넣어도 뜻대로 변환됩니다.

### 원칙 6. 결과는 표준이다

출력은 언제나 표준 HTML, CSS, 자바스크립트입니다. weber 만 이해하는 런타임이나 표기를 결과물에 남기지 않습니다.

### 엄격함은 선택

유연한 기본값이 맞지 않는 상황(큰 프로젝트, 자동 생성된 코드 검사 등)을 위해 **엄격 모드**를 둡니다.
엄격 모드에서는 경고가 오류가 됩니다. [10.3](10-settings.md#103-엄격-모드)을 보세요.

## 1.3 이 문서를 읽는 법

### 상태 표시

각 기능 절의 제목 아래에는 상태가 적혀 있습니다.

- **상태: 구현됨** — 현재 컴파일러(1.0.0)가 이미 이렇게 동작합니다. 이 절의 예제는 테스트(`tests/spec.test.ts`)가 실제로 변환해서 확인합니다.
- **상태: 예정** — 명세로 확정했지만 아직 구현하지 않았습니다. 예제는 구현 목표입니다.

하위 절(예: 6.2.1)에 상태 표시가 없으면 위 절의 상태를 따릅니다. 표의 줄마다 상태가 다르면 표 안에 적습니다. 전체 목록은 [부록 C](appendix-c-status.md)에 있습니다.

### 예제

예제는 weber 코드와, 그 코드가 변환된 HTML 을 짝지어 보여 줍니다.
HTML 예제는 컴파일러의 실제 출력 형식(들여쓰기, 줄바꿈)을 따릅니다. 길어서 일부만 보일 때는 `...` 로 줄입니다.

### 규칙의 말투

- "~한다", "~이다": 반드시 그렇게 동작합니다.
- "~할 수 있다": 쓰는 사람이 선택할 수 있습니다.
- "경고한다": 변환은 계속하되 진단 메시지를 남깁니다.
- "오류다": 변환을 멈춥니다.

## 1.4 용어

| 용어 | 뜻 |
| --- | --- |
| 문장 | 한 줄(또는 `;` 로 나눈 한 조각)의 weber 코드. `p: "안녕"` 같은 것 |
| 키 | 문장 맨 앞의 이름. `p`, `color`, `onclick` 같은 것 |
| 값 | 키 뒤에 오는 내용. `p: "안녕"` 의 `"안녕"` |
| 블록 | `{ }` 나 들여쓰기로 묶은 문장들 |
| 판별 | 키가 요소·속성·CSS·JS 중 무엇인지 정하는 일 ([3장](03-classification.md)) |
| 문맥 | 판별에 쓰이는 주변 정보. 주로 그 문장을 감싸는 요소 |
| 설탕 | 더 짧게 쓰기 위한 표기. 같은 결과를 내는 긴 표기가 항상 따로 있다 |
| 추측 | 쓰는 사람이 명시하지 않은 것을 weber 가 정하는 일 (단위, 태그 이름 등) |
| 지시문 | `@` 로 시작해 변환 방식을 정하는 문장. `@include`, `@set` 같은 것 |
| 문서 | `<!DOCTYPE html>` 로 시작하는 완전한 HTML 출력 |
| 조각 | 쓴 내용만 담은 HTML 출력 |

## 1.5 범위 밖

weber 는 HTML 문서를 만드는 언어입니다. 다음은 하지 않습니다.

- 실행 중의 상태 관리나 반응형 렌더링 (React, Vue 같은 것)
- 자바스크립트의 변환, 번들링, 압축
- 서버에서 도는 로직
- 계산과 함수가 있는 CSS 전처리기 (Sass 의 `@function`, `@mixin` 같은 것). 재사용은 [9장](09-reuse.md)의 변수와 컴포넌트로 합니다.

자바스크립트와 CSS 는 손대지 않고 그대로 출력하는 것이 기본입니다. weber 가 바꾸는 것은 weber 문법으로 쓴 부분뿐입니다.
