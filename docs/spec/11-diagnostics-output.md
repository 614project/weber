# 11. 진단과 출력

[← 10. 설정](10-settings.md) · [목차](../README.md) · 다음: [부록 A. 문법 요약 →](appendix-a-grammar.md)

이 장은 weber 가 쓰는 사람에게 알려 주는 것(오류, 경고, 설명)과, 결과 HTML 의 모양을 정합니다.

## 11.1 오류

> 상태: 구현됨

오류는 변환을 계속할 수 없을 때 냅니다. 위치(파일:줄:칸)와 함께 그 줄의 코드를 보여 줍니다.

```text
weber 오류: 문자열이 닫히지 않았습니다. 여러 줄 텍스트는 백틱(`)으로 감싸세요. (index.weber:2:8)
 1 | body {
 2 |     p: "안녕
   |        ^
```

| 오류 | 예 | 상태 |
| --- | --- | --- |
| 닫히지 않은 문자열·주석·코드 블록 | `p: "안녕` | 구현됨 |
| 짝이 맞지 않는 `}` | 열지 않은 블록을 닫음 | 구현됨 |
| 한 줄에 두 문장 | `p { "a" "b" }` | 구현됨 |
| 잘못된 이스케이프 | `"\u{zz}"` | 구현됨 |
| 내용을 가질 수 없는 요소에 내용 | `br: x`, `img { p: "x" }` | 구현됨 |
| 조각의 최상위에 속성이나 CSS | `color red` 만 있는 파일 | 구현됨 |
| CSS 속성에 값이 없음 | `color` | 구현됨 |
| 닫히지 않은 블록 | 파일이 `div {` 로 끝남 | 구현됨 (예정: 경고로 바꿈, [2.10](02-syntax.md#210-닫히지-않은-블록)) |
| 정의되지 않은 컴포넌트 | `cardd("x")` | 예정 |
| 파일을 찾을 수 없음, 순환 포함 | `@include "없는파일.weber"` | 예정 |
| 엄격 모드의 모든 경고 | | 예정 |

API 에서는 `WeberError` 를 던집니다. `line`, `column`, `frame`(위의 코드 조각), `reason`(위치를 뺀 메시지) 속성이 있습니다.

## 11.2 경고

> 상태: 구현됨 (경고 코드는 예정)

경고는 변환은 하되 실수일 수 있는 곳에서 냅니다. 오타로 보이면 비슷한 이름을 제안합니다.

```text
경고: 알 수 없는 이름 'colr'을(를) HTML 속성으로 처리했습니다. 혹시 'color'인가요? (index.weber:2:5)
경고: 'href'은(는) <div> 요소에서 쓰이지 않는 속성입니다. (index.weber:3:5)
```

경고에는 코드가 붙습니다(예정). 코드는 `@set ignore 코드` 로 숨길 때 씁니다.

| 코드 | 언제 | 상태 |
| --- | --- | --- |
| `unknown-name` | 모르는 이름을 속성으로 처리했을 때 | 구현됨 |
| `misplaced-attribute` | 요소에 맞지 않는 속성 | 구현됨 |
| `duplicate-attribute` | 같은 속성을 여러 번 씀 | 구현됨 |
| `unknown-element` | 블록이 붙은 키가 알려진 요소가 아님 | 구현됨 |
| `css-property-block` | CSS 속성 이름에 블록이 붙음 | 구현됨 |
| `unknown-css-property` | CSS 블록 안의 모르는 속성 | 구현됨 |
| `script-src-block` | `script { src … }` | 구현됨 |
| `undefined-variable` | 정의되지 않은 변수 | 예정 |
| `duplicate-variable` | 같은 블록에서 변수를 두 번 선언 | 예정 |
| `missing-argument` | 기본값 없는 컴포넌트 인자를 주지 않음 | 예정 |
| `shadowed-element` | 컴포넌트 이름이 HTML 요소 이름과 같음 | 예정 |
| `auto-closed` | 파일 끝에서 블록을 자동으로 닫음 | 예정 |
| `unknown-layout-word` | `layout` 의 모르는 낱말 | 예정 |
| `link-rel` | `link` 의 `rel` 을 추측하지 못함 | 예정 |
| `duplicate-setting` | 같은 설정을 여러 번 씀 | 예정 |

```text
경고[unknown-name]: 알 수 없는 이름 'colr'을(를) HTML 속성으로 처리했습니다. 혹시 'color'인가요? (index.weber:2:5)
```

## 11.3 설명

> 상태: 예정

weber 가 추측하거나 채워 넣은 것은 경고가 아니므로 평소에는 보이지 않습니다. `--explain` 옵션을 주면 모두 보여 줍니다. ([원칙 3](01-overview.md#원칙-3-추측은-드러낸다))

```text
index.weber:3:5   판별     title → 속성 (요소 안의 title)
index.weber:4:5   단위     font-size 16 → 16px
index.weber:7:1   끌어올림  <title> → <head>
index.weber:9:3   감싸기   li 2개 → <ul>
index.weber:12:5  태그     .item → li (부모가 ul)
index.weber:1:1   채움     <meta name="viewport">
```

API 에서는 `compile()` 결과의 `notes` 에 같은 내용이 `{ kind, message, line, column }` 으로 담깁니다.

## 11.4 출력 형식

> 상태: 구현됨

### 줄바꿈과 들여쓰기

weber 는 **화면에 보이는 결과가 바뀌지 않는 곳에만** 줄바꿈과 들여쓰기를 넣습니다. HTML 에서 인라인 요소 사이의 줄바꿈은 공백으로 보이기 때문입니다.

- 형제 사이에는, 둘 중 하나라도 블록 요소(`div`, `p`, `li`, `script` …)일 때만 줄을 바꿉니다.
- 블록 요소의 내용이 여러 줄이면, 여는 태그 뒤와 닫는 태그 앞에서도 줄을 바꿉니다.
- 텍스트와 인라인 요소(`a`, `span`, `b` …) 사이에는 줄을 바꾸지 않습니다.
- SVG 와 MathML 의 컨테이너 안에서는 요소 사이의 공백이 무시되므로 어디서든 줄을 바꿉니다.
- `pre`, `textarea` 의 내용은 그대로 둡니다. 내용이 줄바꿈으로 시작하면 HTML 파서가 첫 줄바꿈을 지우므로 하나를 더 넣습니다.

```weber
div {
    p: "블록 요소 사이에서는 줄을 바꿉니다"
    "텍스트와 "
    b: "인라인 요소"
    "는 붙여 씁니다"
}
```

```html
<div>
  <p>블록 요소 사이에서는 줄을 바꿉니다</p>
  텍스트와 <b>인라인 요소</b>는 붙여 씁니다
</div>
```

### 이스케이프

- 텍스트의 `<`, `>` 는 `&lt;`, `&gt;` 로 바꿉니다. `&` 는 문자 참조로 오해될 수 있을 때(뒤에 영문자, 숫자, `#` 이 올 때)만 `&amp;` 로 바꿉니다.
- 속성값은 `"` 와 모호한 `&` 를 바꿉니다. 값에 `"` 가 있고 `'` 가 없으면 작은따옴표로 감싸서 바꾸지 않습니다.

```weber
p: "<b> & 기호"
a { title 'say "hi"'; href "?a=1&b=2" }
```

```html
<p>&lt;b&gt; & 기호</p>
<a title='say "hi"' href="?a=1&amp;b=2"></a>
```

### 그 밖의 규칙

- **속성 순서**: 선택자 축약에서 나온 순서, 그다음 문장 순서입니다. `class` 와 `style` 은 처음 나온 자리에 한 번만 나옵니다.
- **빈 요소**: HTML 의 빈 요소는 `<br>` 처럼 닫는 표시 없이, SVG·MathML 의 빈 요소는 `<circle />` 처럼 씁니다.
- **결정성**: 같은 입력과 설정이면 언제나 같은 출력입니다. 자동으로 붙는 `weber-번호` 클래스도 소스의 순서로 정해집니다.
- **문서의 끝**: 줄바꿈 하나로 끝납니다.
- **들여쓰기**: 기본은 스페이스 2칸입니다. 명령줄의 `--indent 4`·`--indent tab`, API 의 `indent` 로 바꿉니다.
- **압축**: `--minify`(API 의 `minify: true`)를 주면 줄바꿈과 들여쓰기 없이 출력합니다. CSS 도 압축합니다. 자바스크립트는 손대지 않습니다.
